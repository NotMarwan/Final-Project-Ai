# EXP-1404 Evidence-ring formats + aliasing (WT-10 E-6) — memory before/after

- Hypothesis: storing the evidence ring as JPEG-q90/NV12 records cuts ring memory ~10x/2x versus raw BGR at 960x540 (WT-10 §3.2 math: 222 MiB vs ~22 MiB per camera at 30 fps x 5 s) while decode-at-assembly keeps the _write_evidence_clip contract and evidence provenance (960-max-side INTER_AREA full-frame, no crop; no upscaling — mixed-size windows are letterboxed/downscaled, never enlarged). Ring payloads must never alias the capture buffer and derived inference views must never contaminate evidence (E-6 regression).
- Requirement link: F-21/F-22 (evidence clip + ledger, storage stage), F-05 (downscale + IPC separation), G-06 (evidence quality path), SC-8 (layout unchanged).
- Baseline: commit e86d34b; ring entries (captured_at, frame) tuples of raw BGR 960-max-side arrays in deque(maxlen=600) trimmed to 5.0 s; post queue queue.Queue(maxsize=360) of the same tuples; downscale_for_inference passthrough returns the same array when no scaling is needed (documented aliasing hazard).
- Candidate: commit e7dc49e/7e4e5d6; EvidenceFrame records (captured_at, payload, fmt, sequence, width, height) with fmt=bgr|jpeg90|nv12 (default bgr = exact pixels, unchanged provenance); make_evidence_frame copies only in the passthrough-alias case (resize outputs stored as-is, zero avoidable copies); materialize_evidence_samples + DecodedPostQueue decode on the writer thread (3.4 ms/frame, WT-10 P-3) preserving the (stamp, frame) writer contract; fit_evidence_frame never upscales.
- Success criteria (BEFORE results): (1) measured ring payload totals: jpeg90 <= 25% of raw bytes, nv12 ~= 50% of raw bytes over n=150 real 960x540 frames; (2) jpeg90 roundtrip PSNR > 30 dB on camera-meaningful content and decoded shape identical; (3) aliasing regression: mutating the capture buffer after ring append changes nothing in the ring payload, and mutating the inference view changes nothing in evidence (both directions); (4) mixed-size window re-fits to one canvas with adjusted>0 and content region byte-identical (letterbox), never enlarged; (5) writer contract: DecodedPostQueue yields (stamp, frame) tuples and passes the None sentinel.
- Failure criteria / rollback: any aliasing/mutation leak, any upscale, or jpeg90 ratio > 25% rejects the compressed modes (keep bgr only) — candidate stays only in bgr mode.
