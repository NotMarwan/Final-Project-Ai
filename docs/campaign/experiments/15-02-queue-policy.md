# EXP-15.02 Queue policy: drop-newest vs latest-wins under backlog

- Hypothesis: Under a capture rate that exceeds sustained inference throughput, the current drop-newest policy (producer `put_nowait` + `except queue.Full: pass`, api.py camera_worker) makes the worker process STALE-but-QUEUED frames, inflating `frameAgeMs` and decision staleness, while consumer-side latest-wins (drain stale queued packets before processing) processes FRESH frames and cuts `frameAgeMs` p95 — at the cost of wider sequence gaps that invalidate temporal windows per G-07 (gap bound 2.1/fps). The decision staleness trade-off is measured both ways: stale-but-latest (drop-newest keeps the oldest queued frames; the newest is discarded at the producer) vs fresh-but-queued (latest-wins discards queued frames to reach the newest).
- Requirement link: WT-15 step 2; G-07 (invalid windows rejected); R-2 (drop accounting); F-12; queue sizes 3/30 remain bounded and frozen.
- Baseline: identical to EXP-15.01 baseline block (same commit set, hashes, preprocessing, decision config, env); policy `drop-newest` (= deployed behavior); workload 90 s synthetic-file-media replay at 30 fps, 720p → 640 view; run A = baseline policy.
- Candidate: policy `latest-wins` (consumer-side drain in `inference_worker`, `AI_SENTINEL_QUEUE_POLICY=latest-wins` or config `queue_policy`); run B = same workload. Producer-side drop-oldest is NOT implemented in this slice (needs an api.py/CaptureQuality hunk) and is out of scope unless run B shows a verdict gap.
- Success criteria (defined BEFORE inspecting results): adopt `latest-wins` iff (i) `frameAgeMs` p95 improves ≥20% and `violence_observation_age_ms` median does not regress, AND (ii) the full-window valid rate (window_contract.invalid_full_window_rate) does not drop by more than 0.05 absolute vs run A, AND (iii) `frameQueueDroppedDerived` stays consistent with the producer drop count (divergence only from documented discard paths). Otherwise KEEP `drop-newest` (which also keeps windows valid at the 2.1/fps gap bound under mild drops). Either verdict keeps queue sizes bounded (3/30).
- Failure criteria / rollback: if latest-wins crashes the worker (drain exceptions on non-mp queue abstractions) or widens gaps such that >5% more full windows are invalid, reject; revert = default remains `drop-newest` (env/config switch stays for experiment replay).
- Result: MEASURED (same lock window as EXP-15.01; run A drop-newest n=2694, run B latest-wins n=2700; artifacts 15-02-runA/15-02-runB JSON, hashes in EXP-15.01). FrameAgeMs p05/median/p95: A 0.87/1.26/1.71 ms vs B 0.85/1.15/1.95 ms — no improvement. backlogFrames: A median 0 max 3; B median 0 max 0. CRITICAL FINDING: the policy never engaged — `frameQueueDiscardedByPolicy` = 0 in BOTH runs (and frameQueueDroppedDerived 6→A / 0→B with producer drops 6/0: run variance at startup). At the deployment workload (30 fps, 720p→640, CUDA models, violence async @stride 8) the worker sustains real time (loop cost ≈1.5 ms/frame), so NO stale-but-latest regime arises: decision staleness is identical across policies (violence_observation_age_ms median 125 ms both, stride-cadence dominated). Window validity: A invalid_full_window_rate 0.0083 (caused by its 6 startup drops), B 0.0 — latest-wins created ZERO invalid windows here because it discarded nothing. Decision staleness measured both ways as required: under zero backlog both modes degenerate to the same fresh-but-queued stream.
- Verdict: keep (drop-newest stays the default; latest-wins REJECTED by pre-registered criterion (i): no ≥20% frameAgeMs p95 improvement — in fact no measurable effect). The `AI_SENTINEL_QUEUE_POLICY=latest-wins` switch remains available and test-covered (unit tests prove drain + discard accounting + R-2 non-corruption) as an experiment knob. UNMEASURED regime: sustained overload (backlog > 0) — the only regime where the policies differ — not reachable at the measured workload; recommended follow-up: repeat runs under CPU-EP or ≥60 fps capture to force backlog, then re-evaluate both staleness directions.
- Cold vs warm: warm steady state after model load (cold measured in EXP-15.04). Frame age is single-clock (declared capture base; `perf-qpc` in the harness for resolution — GetTickCount64 quantization of the deployed mono stamp is ±1 tick, labeled).
