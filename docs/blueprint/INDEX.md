## Status semantics

- `implemented-active`: implementation is present and connected in the reviewed candidate source; this is not runtime acceptance, accuracy, or readiness evidence
- `partial`: implementation is present with a known contract, dependency, or coverage gap
- `disconnected`: code exists but has no live caller / cannot be reached from the committed tree
- `proposed`: declared or decided only; not implemented
- `unverified`: the stated runtime or product behavior has not been established by suitable evidence
- `findings`: for kind=finding, status preserves the state of the affected surface at the pinned baseline; candidate fixes are described in feature entries and canonical docs
- `slices`: for kind=slice, status summarizes source integration only; it does not imply that every linked feature, dependency, or acceptance gate passed
